1. First understand what Automated Underground Mine Design actually means
An underground mine is not simply a collection of tunnels. It is a carefully optimized system involving geological, economic, geotechnical and operational constraints.






















10











Consider a hypothetical underground gold deposit.

You have:
- A 3D geological model containing orebody geometry.
- Ore grades at different spatial locations.
- Rock-mass properties.
- Economic parameters such as gold price and mining cost.
- Mining method constraints.
- Equipment and production constraints.
The objective is to determine:
1. Where should the underground mine be developed?
2. Where should access tunnels, ramps and levels be constructed?
3. Which portions of the orebody should be extracted?
4. What should be the dimensions and locations of stopes?
5. How can we maximize economic value while satisfying mining constraints?
This is the fundamental problem.

Dataset 3: Binary Integer Linear Programming for Stope Layout Optimization
Essential research reference










A Binary Integer Linear Programming Model for Optimizing Underground Stope Layout

Mensah and Awuah-Offei, 2025.
Read the research paperAccess the research code and data

This is one of the most relevant references for your proposed project.

The paper formulates stope-layout optimization as a Binary Integer Linear Programming (BILP) problem.

In simplified terms:
- Divide the deposit into candidate mining regions.
- Define whether each candidate stope is selected or not.
- Assign economic value to each candidate.
- Introduce constraints to prevent overlapping stopes and enforce pillar requirements.
- Find the combination that maximizes the objective function.
For example, a binary variable:
\[
x_i =
\begin{cases}
1 & \text{If stope }i\text{ is selected}\\
0 & \text{Otherwise}
\end{cases}
\]

A simplified objective:
\[
\max Z=\sum_{i=1}^{n}V_i x_i
\]

Where:
- \(V_i\) = economic value of candidate stope \(i\).
- \(x_i\) = selection variable.
The actual paper contains a more detailed optimization formulation. It also discusses extending the model to 3D and addressing diagonal pillar constraints. 
Springer Link


My suggestion: Download the GitHub repository first. Examine its data structures, objective function, constraints and solver implementation. This can save substantial research time.

5. How will our automated mine-design system actually work?
Let's take a practical example.

Suppose we have a hypothetical underground gold deposit with 10,000 geological blocks.

Each block contains:
- Spatial coordinates.
- Gold grade.
- Density.
- Block dimensions.
- Geological classification.








wallstreet-online.de


Step 1: Import the geological block model
The input might be a CSV file:
X	Y	Z	Grade (g/t)	Density
100	200	-100	2.5	2.7
110	200	-100	3.1	2.7
120	200	-100	0.4	2.6
100	210	-100	4.2	2.8
110	210	-100	1.8	2.7

These are illustrative values, not actual Lisheen data.

First, visualize the block model in 3D.
Step 2: Identify economically mineable blocks
You need to calculate the economic value of each block.

A simplified expression:
\[
V_i = T_i \left(G_i R P-C_i\right)
\]

Where:
- \(V_i\) = economic value of block.
- \(T_i\) = block tonnage.
- \(G_i\) = grade.
- \(R\) = metallurgical recovery.
- \(P\) = revenue per unit of recovered metal, adjusted for the grade and unit conversion.
- \(C_i\) = mining and processing cost per tonne.
You also need to consider cutoff grade and mining dilution.

The algorithm should not simply select all blocks with high grades. A block might have high grade but be inaccessible or impossible to mine economically.
Step 3: Generate candidate stopes








link.springer.com


A stope is an underground excavation from which ore is extracted.

You can generate candidate stopes using:
- Minimum and maximum stope width.
- Minimum and maximum stope height.
- Minimum strike length.
- Geological continuity.
- Minimum pillar width.
- Geotechnical constraints.
For example, suppose your system generates 100 possible stope configurations.

Each candidate will contain a collection of blocks.

Your algorithm must decide which candidates should be selected.
Step 4: Optimize the stope layout
This is where Operations Research becomes important.

You can formulate the problem as:
\[
\max \sum_{i=1}^{n}V_i x_i
\]

Subject to:

Geometric constraints
- Stope dimensions must be within allowed limits.
- Stopes must follow the orebody geometry.
Pillar constraints
- Adjacent stopes must maintain minimum pillar dimensions.
- Overlapping stopes must not be selected.
Geotechnical constraints
- Maintain acceptable ground stability.
- Respect extraction ratios and ground-condition restrictions.
Economic constraints
- Maximize economic value.
- Consider dilution, recovery and operating costs.
You can solve this using Mixed Integer Linear Programming (MILP), Binary Integer Linear Programming (BILP), or suitable heuristic methods.

This is a better starting point than applying deep learning directly to mine design.
Step 5: Generate the 3D mine design






















13











Once the stopes have been optimized, visualize:
- Selected stopes.
- Unselected ore blocks.
- Pillars.
- Access tunnels.
- Development levels.
For the first prototype, concentrate on stope geometry and its constraints. Automated access-network design can be introduced as a separate module.
Step 6: Evaluate the output
You need to establish whether your algorithm actually improves the design.
Evaluation parameter	What it measures
Total economic value	Financial performance
Ore recovery	Proportion of ore extracted
Dilution	Waste material included in extraction
Pillar volume	Material left for structural support
Stope utilization	How effectively the orebody is mined
Development length	Required access infrastructure
Constraint violations	Technical feasibility

Compare your results with an existing mine design or a conventional optimization method.

This comparison is what will turn the software implementation into research.
6. Where does Machine Learning fit into this project?
One thing I would strongly recommend: do not force ML into every component.

Mine design is fundamentally a constrained optimization problem. Operations Research is often more suitable than supervised ML for deciding which stopes to select and how they should be arranged.

However, ML can improve several parts of the process.
Component	Possible technique
Orebody identification	DBSCAN, PCA
Grade estimation	Ordinary Kriging, Random Forest
Rock-mass classification	Random Forest, XGBoost
Stope selection	MILP, BILP, Genetic Algorithm
Stope shape optimization	Heuristics, mathematical optimization
Economic uncertainty	Monte Carlo Simulation
Design parameter optimization	Bayesian Optimization

A possible advanced research direction would be:

Hybrid ML + Operations Research Framework for Automated Underground Mine Design.

This could be a stronger research contribution than simply implementing a Genetic Algorithm.
