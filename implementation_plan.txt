OBJECTIVE:
Build a working prototype that demonstrates automated underground mine design
using a block model, stope optimization via BILP, and an interactive 3D web
visualization — suitable for academic research and industry demonstration.

================================================================================
PHASE 1: DATA PREPARATION
================================================================================

Step 1.1 — Generate Synthetic Block Model
  - Create a realistic 3D block model (CSV) representing a gold deposit
  - Each block: X, Y, Z coordinates, gold grade (g/t), density (t/m³),
    rock type, RQD (Rock Quality Designation)
  - Block dimensions: 5m x 5m x 5m
  - Grid size: ~40x30x20 = 24,000 blocks
  - Grade distribution: simulated using random fields with spatial correlation
    to mimic real orebody geometry (high-grade core with grade halo)
  - Output: data/block_model.csv

Step 1.2 — Calculate Economic Block Values
  - For each block compute: V = Tonnage * (Grade * Recovery * Price - Cost)
  - Parameters: Gold price $1,900/oz, Recovery 92%, Mining cost $45/t,
    Processing cost $25/t, G&A $10/t
  - Classify blocks: ore (V > 0) vs waste (V <= 0)
  - Apply cutoff grade filter
  - Output: data/economic_block_model.csv

================================================================================
PHASE 2: STOPE OPTIMIZATION ENGINE
================================================================================

Step 2.1 — Candidate Stope Generation (Floating Stope Algorithm)
  - Define stope dimension constraints:
    Min width: 5m, Max width: 20m
    Min height: 10m, Max height: 30m
    Min strike length: 10m, Max strike length: 25m
  - Sweep stope template across block model
  - For each position, calculate total economic value of enclosed blocks
  - Generate candidate stope list with geometry and value
  - Output: list of candidate stopes with block memberships

Step 2.2 — Stope Layout Optimization (Binary Integer Linear Programming)
  - Formulate as BILP:
    Maximize: Z = sum(V_i * x_i) for all candidate stopes i
    Subject to:
      - Non-overlap: no two selected stopes share a block
      - Minimum pillar width between adjacent stopes (5m)
      - Stope dimension constraints (enforced in generation)
  - Solve using PuLP + HiGHS (open-source solver)
  - Output: optimized set of selected stopes

Step 2.3 — Economic Evaluation
  - Calculate total NPV, ore recovery, dilution, tonnage
  - Compare: optimized layout vs greedy selection vs all-candidates
  - Generate summary statistics table

================================================================================
PHASE 3: MINE LAYOUT GENERATION
================================================================================

Step 3.1 — Access Development Network
  - Generate simplified decline/ramp from surface to deepest level
  - Create level access drives at each mining level
  - Connect levels to stopes via crosscuts
  - Calculate development metres and cost

Step 3.2 — Pillar Design
  - Identify crown, sill, and rib pillars between stopes
  - Calculate pillar dimensions and stability metrics
  - Flag any pillars below minimum width threshold

PHASE 6: NEXT-LEVEL FEATURES — PRODUCTION SCHEDULING & GEOTECHNICAL ASSESSMENT
================================================================================

Step 6.1 — Production Scheduling with DCF NPV
  - Grade-priority scheduling: assign stopes to periods in descending grade
  - Configurable annual mining rate (default 500,000 t/year)
  - Per-period metrics: tonnage, metal produced, revenue, operating costs,
    development cost allocation, net cash flow
  - Discounted Cash Flow (DCF) analysis with configurable discount rate
  - Cumulative DCF NPV tracking across mine life
  - Visualizations: period cash flow waterfall, cumulative DCF curve,
    tonnage profile, grade profile per period
  - Module: src/production_scheduler.py
  - API: /api/schedule (POST)
  - Frontend: Tab 8 — Production Schedule

Step 6.2 — Geotechnical Stability Assessment
  - Stope stability analysis:
    • Depth-based in-situ stress (σv, σh) with configurable K-ratio
    • UCS (Uniaxial Compressive Strength) with rock mass variability
    • Stability Number = UCS / σ_max → risk classification
      (Low / Medium / High / Critical)
    • Hydraulic radius calculation per stope
  - Mathews Stability Graph method:
    • Q-system rock mass quality estimate (RQD-based)
    • Mathews N calculation with depth, geometry, and gravity factors
    • Zone classification: Stable / Transitional / Caving
  - Pillar assessment:
    • Identify adjacent stope pairs within proximity threshold
    • Calculate pillar stress using tributary area method
    • Pillar strength via empirical formula (UCS × 0.6 × √(W/H))
    • Factor of Safety → Adequate (>1.5) / Marginal (1.0–1.5) / Inadequate (<1.0)
    • Flag pillars below minimum width threshold
  - Visualizations: risk distribution pie, pillar status bar chart,
    stability number vs depth scatter, Mathews zone classification
  - Module: src/geotechnical.py
  - API: /api/geotechnical (POST)
  - Frontend: Tab 9 — Geotechnical Assessment

Step 6.3 — Flask Web Platform Migration
  - Migrated from Streamlit to Flask + HTML5/CSS3/JavaScript
  - RESTful API architecture with JSON endpoints
  - Plotly.js client-side rendering (no server-side figure generation)
  - Responsive dark-themed UI with per-tab inline loading indicators
  - Landing page with feature showcase and industry comparison
  - Render-ready deployment (PORT environment variable)

PHASE 7: GEOSTATISTICS, MULTI-SCENARIO COMPARISON & HEALTH ENDPOINT
================================================================================

Step 7.1 — Health Check Endpoint
  - Added /healthz route returning JSON {"status": "ok", "service": "..."}
  - Used by Render/cloud load balancers to verify app is alive
  - API: /healthz (GET)

Step 7.2 — Ordinary Kriging Grade Estimation
  - Full geostatistical workflow alongside existing ML grade prediction
  - Experimental variogram: computes semivariance γ(h) for lag bins
  - Variogram model fitting: Spherical, Exponential, Gaussian (least-squares grid search)
  - Ordinary Kriging interpolation with moving neighborhood (up to 20 neighbors)
  - Kriging variance (σ²_k) for spatial uncertainty quantification
  - Cross-validation: hold-out R², RMSE, MAE
  - Visualizations: experimental vs fitted variogram, actual-vs-predicted scatter,
    3D kriged grade map with variance
  - Module: src/kriging.py
  - API: /api/kriging (POST)
  - Frontend: Tab 10 — Kriging

Step 7.3 — Multi-Scenario Comparison
  - Save any number of optimization runs as named scenarios in server memory
  - Each scenario stores: name, economic parameters, optimization summary
  - Compare side-by-side: NPV, tonnage, average grade, stope count across all scenarios
  - Side-by-side bar charts for rapid what-if analysis
  - Delete individual or all scenarios
  - API: /api/scenarios (GET), /api/scenarios/save (POST),
         /api/scenarios/compare (POST), /api/scenarios/delete/<id> (DELETE)
  - Frontend: Tab 11 — Scenarios
